# AI ассистент с доступом к базе знаний

Консольное приложение и Telegram-бот отвечают на вопросы о продуктах LoveSelf. Ответ собирается по схеме RAG: вопрос сопоставляется с каталогом, из него берутся подходящие фрагменты, и модель OpenAI формулирует ответ только по этим фрагментам.

Каталог лежит в `assistant_api/data/loveself-products.txt`. При первом запуске он разбивается на фрагменты и сохраняется в локальной базе Chroma. Повторный вопрос берётся из кеша, без нового обращения к модели.

## Что можно делать

- Задать вопрос в консоли или в Telegram и получить ответ на русском языке.
- В консоли посмотреть статистику базы и кеша и очистить кеш ответов.
- В Telegram получить приветствие, справку и статистику. В чат отправляется только текст ответа, без списка источников.
- Проверить качество ответов скриптом оценки RAGAS.

Консоль и бот используют одну и ту же базу и один и тот же кеш. Запускайте что-то одно.

## Из чего состоит проект

Все команды ниже выполняются из папки `assistant_api`.

| Файл | Назначение |
| --- | --- |
| `app.py` | Консольный чат |
| `telegram_bot.py` | Telegram-бот |
| `rag_pipeline.py` | Поиск по каталогу, запрос к модели и кеш |
| `vector_store.py` | Разбиение каталога на фрагменты, создание эмбеддингов и поиск в Chroma |
| `cache.py` | Создание кеш-пары «вопрос — ответ» в SQLite |
| `evaluate_ragas.py` | Оценка Faithfulness, Context Precision и Answer Relevancy |
| `data/loveself-products.txt` | Текст каталога |

`app.py` и `telegram_bot.py` — два способа задать вопрос. Остальные файлы подключаются ими сами. `vector_store.py` и `rag_pipeline.py` можно запустить напрямую: тогда выполнится их самопроверка, а не чат.

## Что нужно для запуска

- Python 3.12
- Ключ OpenAI API. Он нужен и для эмбеддингов `text-embedding-3-small`, и для ответов модели `gpt-4o-mini`
- Для бота — токен Telegram, который выдаёт [@BotFather](https://t.me/BotFather)
- Для оценки RAGAS дополнительно используется модель `gpt-4.1` как судья метрик

Ключи хранятся в `assistant_api/.env` файле, который нужно создать.

```
OPENAI_API_KEY=ваш_ключ
TELEGRAM_BOT_TOKEN=ваш_токен
```

Для консоли и оценки достаточно `OPENAI_API_KEY`. `TELEGRAM_BOT_TOKEN` нужен только боту.

## Установка

В PowerShell из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Затем перейдите в `assistant_api` и создайте там файл `.env`, как указано выше.

## Консоль

```powershell
python app.py
```

Введите вопрос обычным текстом. Дополнительные команды:

- `stats` — число фрагментов в каталоге, число записей в кеше и модель
- `clear` — удалить сохранённые ответы; файл `api_rag_cache.db` остаётся, каталог в Chroma не затрагивается
- `exit`, `quit` или `q` — выход

## Telegram

Один раз создайте бота в BotFather и впишите его токен в `.env`. Затем:

```powershell
python telegram_bot.py
```

Окно терминала должно оставаться открытым: этот процесс и есть бот. Остановка — Ctrl+C.

В чате с ботом:

- `/start` — приветствие
- `/help` — справка и примеры вопросов
- `/stats` — статистика каталога, кеша и модель
- вопросы, связанные с продуктами компании, обычным текстом

Очистка кеша из Telegram недоступна. Её выполняет команда `clear` в консоли; перед этим бота нужно остановить.

## Оценка качества

```powershell
python evaluate_ragas.py
```

Скрипт прогоняет 8 пар «вопрос — эталонный ответ» через пайплайн без кеша и считает три метрики RAGAS. Запуск занимает несколько минут и расходует квоту OpenAI.

Набор вопросов с ответами написан по каталогу `loveself-products.txt`, отдельно от ответов самой системы. Вопросы сформулированы как ситуации покупателя, а не скопированы из одного абзаца. Часть из них требует назвать сразу два продукта. К каждому вопросу заранее написан эталонный ответ, `ground_truth`: он пересказывает нужные факты каталога и не берётся из ответа, который сгенерировал ассистент.

Mетрики RAGAS:
- **Faithfulness** — насколько сгенерированный ответ опирается на найденные фрагменты каталога, а не добавляет сведения со стороны.
- **Context Precision** — насколько полезные фрагменты стоят выше бесполезных. Фрагмент считается полезным, если подтверждает любую часть эталонного ответа, даже когда остальные части лежат в других фрагментах. Эта метрика сравнивает найденные фрагменты с `ground_truth`.
- **Answer Relevancy** — насколько ответ относится к заданному вопросу. По ответу генерируются вопросы, и их эмбеддинги сравниваются с эмбеддингом исходного вопроса.

Faithfulness и Answer Relevancy эталонный ответ не используют: они смотрят на вопрос, сгенерированный ответ и найденные фрагменты.
